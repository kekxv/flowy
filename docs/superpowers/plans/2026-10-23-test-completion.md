# 测试目标与结束测试闭环

按 writing-plans 与 test-driven-development 技能执行。

1. 后端：将 catalog 迁移为不限于短分类的 objective 文本，保留旧请求字段兼容；运行记录新增 Markdown report。迁移保留已有申请、报告与附件。
2. 权限：开始与结束统一给申请管理者和被分配测试员；测试中明确结束入口。结束必须提供版本、方式、步骤、结果、报告，失败不改状态；不能通过状态接口绕过报告。
3. 前端：采集链接置顶；目标、预期、现象、方式、步骤、结果、报告、流转说明均使用 Markdown。公开编辑器通过采集令牌上传，复用公开大小与数量限制。
4. 验证：权限闭环/API 字段与必填校验、Markdown 表单和开始至结束交互；迁移保留数据；全量测试、build、lint、打印。不启动应用服务。
